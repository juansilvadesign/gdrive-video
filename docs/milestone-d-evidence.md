This file records the evidence needed to ship Milestone D without putting a
Drive URL, file title, cookie path/value, response body, or account identifier in
the repository.

### Secret/config inventory

The audit inspected secret-like filenames and searched every reachable commit for
common private-key, cloud-token, GitHub-token, Google API-key, Google session
cookie, and signed-videoplayback patterns without printing matched values.

- No credential-pattern content was found.
- `.streamlit/secrets.toml` had been added in `8942d4b`. It contained only the
  unused keys `repo`, `branch`, and `file`; no code reads `st.secrets`.
- The unused file was removed. Real `.streamlit/secrets.toml*` files are ignored;
  an explicitly named example remains allowlisted if one is ever needed.
- Cookie export filename patterns were already ignored and are retained.
- No rotation/revocation was indicated by the value-free scan. If a later scan
  finds a usable credential, release work stops until its owner revokes it.

### Legacy behavior characterized at the starting commit

| Simulation | Behavior at `0d4e691` |
| --- | --- |
| Fresh `200` | Streams directly into the final filename; no completion boundary or sidecar. |
| Interrupted transfer | Leaves bytes under the final filename and tells the user to rerun. |
| Server ignores Range | Opens the existing file for append and accepts `200`, corrupting the result. |
| Missing length | Computes the total as the local byte count and can report the file already complete without reading the response. |
| Remote file changed | Has no source validator or persisted identity and can mix old/new bytes. |
| `416` | Treats every response as proof that the local file is complete. |
| Timeout/disconnect | Emits a generic message; no bounded retry or validated rediscovery. |
| Bad cookie input | Loads expired Netscape cookies and accepts domainless raw Cookie headers. |
| Disk/write failure | Reports an OS error after writing directly to the final path; no truthful final/partial distinction. |

The D regression suite replaces each behavior with an explicit expected outcome.

## Fixture policy

Automated tests use a deterministic, generated byte fixture, sanitized form
metadata, and visibly synthetic nonfunctional cookie/query values. CI is offline.
No third-party video or live Drive response is retained.

Manual release fixtures must be maintainer-owned and recorded only by opaque local
labels. Before D can be marked shipped, a maintainer must provide:

- one public video with a locally recorded byte count and SHA-256;
- one private video shared only to a disposable test account;
- one processing or non-video item where practical;
- an exported Netscape jar from the disposable account, deleted after the run.

Do not add fixture IDs, titles, URLs, cookie paths, hashes tied to private titles,
or response captures to this file.
